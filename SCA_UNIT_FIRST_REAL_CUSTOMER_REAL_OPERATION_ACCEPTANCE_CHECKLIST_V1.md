# SCA-Unit First Real Customer Real Operation Acceptance Checklist v1.0

## Purpose
Provide a final acceptance checklist before accepting the first real suitable customer request for the manual SCA-Unit Structural Report service.

## Checklist status
Real operation acceptance checklist.

## Checklist source
This checklist follows the completed real operation record template.

## Acceptance decision rule
Accept only when every required condition is clearly satisfied.

## Required customer materials
- Exactly two JSON structural state files: pending
- First-state and second-state order is clear: pending
- Short explanation of the structural change is provided: pending
- Request is limited to structural comparison: pending

## Required safety checks
- No passwords submitted: pending
- No API keys submitted: pending
- No tokens submitted: pending
- No private keys submitted: pending
- No credentials submitted: pending
- No confidential secrets submitted: pending
- No sensitive personal data submitted: pending
- No unrelated private documents submitted: pending

## Required scope checks
- No legal advice requested: pending
- No financial advice requested: pending
- No medical advice requested: pending
- No cybersecurity assurance requested: pending
- No compliance certification requested: pending
- No full software audit requested: pending

## Pricing confirmation
Preferred first real customer offer: Standard Report at 29 EUR.

## Operator decision
Choose one:
- Accept
- Request correction
- Reject
- Pause for review

## Accept only if
- The request is suitable
- The request is limited
- The files are usable
- The customer understands the service boundary
- No confidential or sensitive material is submitted

## Request correction if
- One file is missing
- File order is unclear
- JSON structure is incomplete
- The explanation is missing
- The customer asks for something outside the service boundary

## Reject if
- Credentials or secrets are included
- Sensitive personal data is included
- The request is unrelated to structural comparison
- The request requires advice outside the service boundary

## Pause if
There is uncertainty about scope, confidentiality, sensitive data, customer expectations, or protected knowledge exposure.

## Protected knowledge rule
This acceptance checklist must not expose AMNE internals or protected structural architecture.

## Final checklist result
Ready to decide on the first real suitable customer request when it arrives.
