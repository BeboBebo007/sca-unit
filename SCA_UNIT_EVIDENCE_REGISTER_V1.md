# SCA-Unit Evidence Register v1.0

## Purpose
Define the official evidence register for SCA-Unit product, engineering, market, and service decisions.

## Core principle
SCA-Unit decisions should be based on evidence, not assumptions.

## What counts as evidence
- Real customer request
- Manual service run result
- User feedback
- Installation issue
- CLI usage issue
- Report generation issue
- Validation failure pattern
- Documentation confusion
- Repeated user need
- Technical test result
- Market comparison finding
- Pricing response

## Evidence record fields
Each evidence record should include:
- Evidence ID
- Date
- Source
- Category
- Description
- Impact
- Decision recommendation
- Status
- Related files or milestones

## Evidence categories
- Product
- Engineering
- Documentation
- Business
- Customer validation
- Pricing
- Market
- Safety
- Protected knowledge boundary

## Decision rule
No major product expansion should be approved without supporting evidence.

## Feature rule
New features should be linked to evidence showing a real user need, technical necessity, or service improvement.

## Pricing rule
Pricing changes should be supported by customer response, service effort, market observation, or operating cost evidence.

## Public claim rule
Public claims should be supported by implemented functionality, test results, or documented service capability.

## Protected knowledge rule
Evidence records must not include AMNE internals, protected structural architecture, customer secrets, credentials, or private submitted customer data.

## Initial evidence baseline
The first evidence baseline is the completed public investment-ready SCA-Unit release and the controlled manual paid Structural Report service workflow.

## Current priority
Collect evidence from the first controlled real customer run before expanding the product scope.
