# SCA-Unit Public Language Cleanup Policy v1.0

## Purpose
Define public wording rules for SCA-Unit so that public documentation remains clear, professional, and focused on the documented product workflow.

## Policy status
Public language cleanup policy.

## Public wording principle
Public documentation should explain what SCA-Unit does, who it helps, and how to use it without naming protected internal systems or unpublished architecture.

## Preferred public language
Use clear public phrases such as:
- documented SCA-Unit workflow
- public workflow
- proprietary internal mechanisms
- protected internal architecture
- public assessment layer
- structural compatibility assessment

## Avoid in public-facing text
Avoid naming internal protected systems, unpublished architecture names, or private research labels in customer-facing documentation.

## README rule
The README should focus on:
- what SCA-Unit is
- how to install it
- how to run it
- what files it accepts
- what report it produces
- how the manual Structural Report service works

## Customer trust rule
Public language should build confidence through clarity, boundaries, and useful examples rather than repeated defensive statements.

## External alignment rule
Public documentation should make SCA-Unit understandable as a Structural Assessment Engine, not only as a JSON comparison utility.

## Final policy result
Public wording is now guided toward clarity, product value, and protection of unpublished internal architecture.
