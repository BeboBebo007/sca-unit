# SCA-Unit Revised First Real Customer Correction Message v1.0

## Purpose
Provide the revised positive-language correction message for the first real customer request when the submitted files or request details need adjustment before processing.

## Message status
Approved public-safe positive customer correction message template.

## Customer correction message

Hello,

Thank you for sending the files for the SCA-Unit Structural Report service.

Your request appears close to the correct workflow. A small correction is needed before I can prepare the structural comparison report clearly and accurately.

SCA-Unit works best when it receives two clearly identified JSON structural state files. This helps produce a readable comparison between the first structural state and the second structural state.

Please review and resend the following:

1. The corrected first JSON structural state file
2. The corrected second JSON structural state file
3. A short note confirming which file represents the first state and which file represents the second state

Please make sure the files are valid JSON and limited to the structural data needed for comparison.

For clarity and good handling, please avoid including passwords, API keys, tokens, private keys, credentials, confidential secrets, unrelated private documents, or sensitive personal data in the files.

This report is a structural comparison report. It is not intended to replace legal, financial, medical, cybersecurity, or compliance advice.

After receiving the corrected files, I will review them again and proceed with the manual report workflow if they match the service scope.

Kind regards,
SCA-Unit

## Internal use note
Use this revised correction message when the request is fixable and should not be treated as a rejection.

## Value rule
This message should make the customer feel guided, not refused.

## Protected knowledge rule
This message must not mention AMNE internals or protected structural architecture.
