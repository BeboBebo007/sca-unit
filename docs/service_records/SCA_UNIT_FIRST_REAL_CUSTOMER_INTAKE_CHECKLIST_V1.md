# SCA-Unit First Real Customer Intake Checklist v1.0

## Purpose
Define the intake checklist for the first real customer request for the manual paid SCA-Unit Structural Report service.

## Core principle
A customer request may be accepted only if it is safe, limited, clear, and compatible with the current manual service boundary.

## Intake status
This checklist is used before accepting or processing the first real customer run.

## Customer request confirmation
- Customer asks for structural comparison: yes/no
- Customer understands this is a manual Structural Report service: yes/no
- Customer understands this is not legal, financial, medical, cybersecurity, or compliance certification: yes/no
- Customer understands that only two JSON structural state files are required: yes/no

## Required customer files
- First JSON structural state file received: yes/no
- Second JSON structural state file received: yes/no
- Customer identified which file is first state: yes/no
- Customer identified which file is second state: yes/no
- Files appear related to the same comparison scope: yes/no

## Safety screening
- No passwords: yes/no
- No API keys: yes/no
- No tokens: yes/no
- No private keys: yes/no
- No credentials: yes/no
- No unrelated private documents: yes/no
- No customer secrets intentionally stored: yes/no

## Scope screening
- Request is limited to structural comparison: yes/no
- Request does not ask for legal certification: yes/no
- Request does not ask for financial certification: yes/no
- Request does not ask for medical certification: yes/no
- Request does not ask for cybersecurity certification: yes/no
- Request does not ask for compliance certification: yes/no

## Acceptance decision
- Accept request: yes/no
- Request correction before acceptance: yes/no
- Reject request: yes/no
- Reason:

## Accepted workflow
If accepted, proceed with the controlled manual report workflow.

## Correction workflow
If correction is required, use the customer correction request template.

## Rejection workflow
If unsafe or out of scope, use the customer rejection template.

## Evidence recording
Record only general evidence. Do not record customer secrets, credentials, private file contents, AMNE internals, or protected structural architecture.
